# GG local EVM test toolchain

The network workspace owns an optional Hardhat development node, listening only
on `127.0.0.1` with chain ID `31337`. This is an ephemeral local EVM test network.
It is not a deployed GG mainnet, a distributed validator network or a bridge.

The Python service supplies four fresh disposable test accounts through
`GG_TESTNET_ACCOUNTS` in the child process environment. No mnemonic, account key
or chain state belongs in this source package. Hardhat's raw startup output must
be discarded because its development console prints account keys.

Dependencies are pinned in `package-lock.json`, installed with lifecycle scripts
disabled under the current user's GG tools directory, and remain supplied by
their original distributors. There is no global npm or PATH modification.

`install_toolchain.py` is the explicit optional toolchain installer. It never
runs on import. Node.js 22.13+ (supported even-numbered releases) is required.

`compile.mjs TOOLCHAIN_DIRECTORY [OUTPUT_JSON]` compiles the public test token
with pinned solc-js 0.8.38 and OpenZeppelin Contracts 5.6.1. It accepts imports only
from that installed OpenZeppelin package. The committed artifact includes ABI,
creation and deployed bytecode, compiler/settings and public source hashes.

`GGTestToken` uses the standard OpenZeppelin ERC20 implementation, six decimals
and a single constructor allocation of 1,000,000 GG-TEST. It has no owner, external
mint, tax or upgrade mechanism. It is not the Solana GGHB token and has no price.

The owned process is launched with:

```
node TOOLCHAIN/node_modules/hardhat/dist/src/cli.js node --config TOOLCHAIN/hardhat.config.mjs --network ggtest --hostname 127.0.0.1 --port OWNED_PORT
```

The working directory is the installed toolchain directory. The public source
plain-JavaScript configuration is copied there as native ESM before launch so
Hardhat can resolve its local installation without spawning a TSX/esbuild
compiler child. The single-process Windows budget remains enforced. It contains
no account values; those remain in the child process
environment. No account or chain state is copied into this package.

The owned node enables both automining and a 2,000 ms interval. Real empty
blocks therefore appear even when there are no transfers; accepted test
transactions still mine immediately. No dummy transaction or synthetic future
block is generated by the UI. The graph retains at most 48 observed headers.
The underlying disposable development chain keeps its own session history;
stop the explicit node session when it is no longer needed.

## Dependency audit, 2026-10-28

The compatible `tmp` dependency override pins the patched version 0.2.7 for
[GHSA-7c78-jf6q-g5cm](https://github.com/advisories/GHSA-7c78-jf6q-g5cm).
The token artifact is unchanged and real contract execution tests pass with
this override.

Hardhat 3.21.1 still requires Zod 3. The current npm audit reports the high
severity [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
against Zod versions before 4.6.6, and propagates that finding to Hardhat and
its Zod utilities. Replacing Zod with an unsupported major version is not a
verified compatibility fix. The GG configuration accepts exactly four accounts
and only fixed local options; no externally supplied configuration collections
are accepted. The development RPC is nevertheless a privileged testing service:
keep it loopback-only, disposable and off when unused. It must not be repurposed
as a public or production node. This dependency audit is not a security audit
of Hardhat or the GG application.
